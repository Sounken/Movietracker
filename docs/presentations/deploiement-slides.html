Domaine 1 · Le site

Ce qu'est vraiment ton site

Le dossier movietracker/ est une application Next.js 16 — pas de simples pages HTML. Elle a besoin de ressources qui tournent en permanence.

🖥️ Serveur Node.js

Rendu côté serveur, routes API, server actions. Il faut un vrai serveur qui tourne.

🗄️ Base PostgreSQL

Via Prisma. Stocke films, notes, comptes utilisateurs. Doit être active en continu.

🔐 Authentification

next-auth gère les connexions et les sessions.

🖼️ Stockage fichiers

@vercel/blob pour les images / imports. À garder ou remplacer.

Domaine 2 · L'hébergement gratuit OVH

Pourquoi ça ne peut pas marcher

❌ Hébergement mutualisé OVH

Sait seulement servir des fichiers statiques (HTML/CSS/JS) et du PHP.

Il ne fait pas tourner Node.js, ni PostgreSQL, ni l'auth côté serveur.

✅ Ce dont ton app a besoin

Un serveur Node actif en permanence + une base de données.

Aucune manipulation ne rend l'hébergement gratuit compatible : ce n'est pas le bon outil.

👉 Les fichiers .html à la racine sont juste d'anciennes maquettes, pas le vrai site.

Domaine 12 · Point d'attention

Le stockage de fichiers (Vercel Blob)

Ton app utilise @vercel/blob. Ce stockage est lié à Vercel — en partant, deux choix :

Option 1 Garder Blob

On crée juste un « Blob store » Vercel et on récupère un jeton (BLOB_READ_WRITE_TOKEN). Utilisable même hors Vercel, palier gratuit. Le plus simple.

Option 2 Changer de stockage

Basculer vers OVH Object Storage ou Cloudflare R2. Plus indépendant, mais demande d'adapter le code.

👉 Rien de bloquant — on commence avec l'Option 1.
